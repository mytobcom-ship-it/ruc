과금 유형별 문제점·대응방안 요약

유형별 문제점 → 대응방안 → 간소화 판정 로직 → 참조 테이블 → PRIM_CHARGEHAND 매핑 순으로 한 화면에서 보기 위한 요약본입니다. 근거·상세 흐름·경고문은 charge-flow.html에, 스키마 원문은 charge-tables.html에 있습니다 — 이 문서는 실무 참조용 압축판입니다.

개방형 OPEN · charge_type=1

⚠ [2026-08-06 발견] 모델 자체가 미확정 — 아래 내용은 확정 설계가 아님

게이트 점(point) 이벤트 모델(아래 플로우차트)로 설계했으나, prim_chargehand(charge_type=1) 293건 실측은 전부 링크 hop 체인 구조(from_id≠to_id, dist_m 채움, 이전 행 to_id=다음 행 from_id)였습니다. 게다가 같은 트립의 prim_tollcharge는 이 체인과 다른 ID로 점(from_id=to_id) 형태를 갖고 있어 두 테이블조차 서로 안 맞습니다. 게이트 점 이벤트 vs 링크 hop 누적거리, 둘 중 뭐가 맞는지 담당자 확인 전까지 미정 — 상세는 charge-flow.html 1절 참고.

문제점

  • base_tollgate.link_id가 실데이터 3건 전부 NULL — 링크ID 매칭 불가
  • GPS는 이산 샘플이라 게이트 좌표에 정확히 안 찍힘
  • [신규] 게이트 점 이벤트 vs 링크 hop 누적거리 — 실측 데이터가 모순(위 경고 참고)

대응방안

  • 게이트 lon/lat과 맵매칭 좌표 간 거리 임계값으로 판정(점 이벤트 채택 시)
  • 기존 HaversineMeters(RawLogWorker.h:162) 재사용, 임계값은 config 신규 파라미터
  • [신규] 링크 hop 누적거리 모델일 가능성도 있어, 코드 착수 전 담당자와 모델 확정 필요

폐쇄형 CLOSED_ROAD · charge_type=2

문제점

  • 개방형과 동일한 link_id NULL 문제 — 좌표 거리 판정만 가능
  • base_tollsection에 없는 (진입,진출) 조합이 나오면 처리 정책 미정
  • [신규] 휴게소 장시간 정차(시동 OFF) 시 진입정보 유실 — 세션이 메모리에만 있어 TTL(기본 1시간) 초과 정차나 트립 재시작(TRIP_ID 변경) 시 진출해도 무과금될 위험

대응방안

  • 게이트 좌표 거리 임계값(개방형과 공유 로직)
  • 미등록 조합은 charge_status=AUDIT로 남겨 추후 확인(잠정 — 확정 필요)
  • [신규] 진입 시 세션+DB 동시 기록(durable), 진출 판정 시 DEVICE_KEY 기준으로도 조회, CLOSED_ROAD 전용 장기 TTL, 일단위 배치로 영구 미종결 스윕

구간단속 SPEED · charge_type=3

문제점

  • base_roadlink엔 link_id/f_node/t_node가 아예 없음 — 순수 좌표 판정만 가능
  • base_mapinfo와 base_roadlink 이중화 — 어느 쪽이 정답인지 미확정
  • GPS 샘플 간격이 넓으면 구간을 통째로 건너뛸 위험

대응방안

  • LINE을 버퍼링해 폴리곤(회랑)으로 변환 → point-in-polygon 판정(주정차용 로직 재사용)

  • 이전~현재 GPS 사이 맵매칭 경로까지 교차판정 확장 필요(놓침 방지, 미구현)

주정차 PARKING · charge_type=4

문제점

  • point-in-polygon 판정 로직 자체가 아직 없음(신규 구현)
  • nDriveStatus(DRIVE_STATUS_PARKED)가 RawLogWorker.cpp에서 아직 안 읽힘
  • 유예시간(10분) 근거가 base_fare 컬럼명(_10min_down/up) 추론뿐 — 확정 아님
  • base_roadlink 실테스트 데이터 1건뿐(검증 부족)

대응방안

  • point-in-polygon 신규 구현(구간단속과 공유)
  • nDriveStatus 판정 진입점 신규 배선
  • 10분을 전역 상수로 잠정 채택 — 담당자 확인 필요

공통 이슈

게이트 계열(개방형·폐쇄형): link_id NULL로 좌표 거리 판정 공유 — 임계값 config 파라미터 하나로 통일 가능.
구역 계열(구간단속·주정차): point-in-polygon 로직 공유 — 구간단속은 LINE을 버퍼링해 폴리곤화하면 동일 함수 재사용.
모든 유형 공통: VEHICLE_TRIP_SESSION 확장 필드 필요(현재 0개), strChargeInsertSQL 실행 코드 없음, 캐시 계층 미구현, GPS 샘플 간 놓침 방지 로직 미구현.
