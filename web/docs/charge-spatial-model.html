과금 유형별 노드·링크·임시ID·폴리곤 공간모델

맵매칭 알고리즘(좌표→링크 스냅) 자체는 제외하고, 맵매칭 결과가 나온 이후 각 과금 유형이 공간을 무엇으로 표현하고(점·구간·구역), 판정 중 어떤 임시 상태(ID·세션)를 들고 있는지만 그림으로 정리한 문서입니다.

상세 판정 흐름은 charge-flow.html, 근거 데이터는 doc/README.txt B·I절 참고 — 이 문서는 공간 표현 방식에만 집중한 보조 자료입니다.

노드 · 지점 링크 · 구간 게이트 · 통과지점 임시ID · 세션/GatePairID 폴리곤 · 구역(zone)

개방형 OPEN · charge_type=1

게이트를 지나는 순간 점(point) 이벤트로 즉시 확정 — 원래 이렇게 설계했지만, 실측 데이터는 전혀 다른 구조를 보여서 어느 모델이 맞는지 아직 미확정입니다.

미해결 — 두 모델 중 확정 전 코드 착수 보류 (doc/README.txt I-7)

폐쇄형 CLOSED_ROAD · charge_type=2

진입 게이트에서 임시ID(GatePairID)를 열고, 링크 체인을 이동하며 거리를 누적하다가 진출 게이트에서 짝을 지어 닫는 구간 짝 이벤트입니다. 이동 중 임시ID가 사라지면(시동 OFF 등) 무과금 위험이 있어 DB에도 같이 남겨두는 대응이 필요합니다.

미해결 — DB durable 기록의 테이블 구조·배치 주기·TTL 임계값 미확정 (doc/README.txt I-8)

구간단속 SPEED · charge_type=3

링크(LINE)를 그대로 쓰지 않고 버퍼링해 폴리곤(회랑)으로 만든 뒤, 진입~진출 구간의 평균속도로 위반을 판정합니다. 판정 결과(Y/N)가 이 단계에서 바로 나온다는 점이 다른 유형과 다릅니다.

미확정 — base_mapinfo vs base_roadlink 이중화, 어느 쪽이 기준인지 담당자 확인 필요

주정차단속 PARKING · charge_type=4

면적을 가진 폴리곤 구역 안에 머무는 체류 이벤트입니다. 거리가 아니라 체류시간이 판정 기준이며, 정차가 시작되는 순간부터 임시ID가 시간을 들고 있다가 이동 재개나 트립 종료 시점에 닫힙니다.

미확정 — point-in-polygon 판정 로직 미구현, 10분 유예시간은 컬럼명 추론뿐
