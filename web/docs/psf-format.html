맵매칭 기반 데이터 파일의 디스크 레이아웃. CreateData(MakeBinary)가 만들고 MapMatchSvr가 읽는다. 두 모듈의 구조체가 바이트 단위로 같아야 한다.

1. 파일 구조

모든 구조체는 #pragma pack(push, 1)으로 패딩 없이 저장된다. 엔진은 각 영역을 fread로 배열에 통째로 읽어들이므로, 필드 하나만 어긋나도 그 뒤 전체가 밀린다.

3. GRID_INFO — 10 bytes

전국을 0.003° 격자로 나눈 셀 하나. 2,667 × 2,334 = 6,224,778셀이 빈 셀까지 전부 미리 생성돼 있어, 좌표로 셀 번호만 계산하면 그 자리의 세그먼트 목록을 바로 얻는다.

셀 크기는 도(degree) 단위라 실제 미터가 위도에 따라 다르다 — 수도권(37.5°N) 기준 가로 265 m × 세로 333 m, 남해안(34.5°N)은 가로 276 m. 코드 주석의 “300m”는 근사치다. 매칭 반경(radius_max=75)이 셀보다 훨씬 작고 3×3 인접 셀을 훑으므로 영향은 없다.

4. GRID_SGMT — 26 bytes

셀 경계로 잘린(clip) 세그먼트. 좌표 기반 후보 검색에 쓰인다.

한 세그먼트가 여러 셀을 가로지르면 셀마다 잘라 각각 등록한다. 그래서 GRIDSGMT_COUNT(11,138,893) ≥ LINKSGMT_COUNT(10,227,751)가 항상 성립해야 한다 — 검증 관문의 불변식.

6. LINK_INFO — 122 bytes (디스크) / 114 bytes (메모리)

링크 1건의 속성. 엔진은 LINK_ID를 키로 unordered_map을 만들고 나머지 114바이트만 값으로 담는다 — 디스크 레코드와 메모리 구조체가 의도적으로 8바이트 다르다.

7. TURN_INFO — 21 bytes

진입 → 진출 회전쌍 1건. 링크별로 연속 배치되며, 엔진은 LINK_INFO.TURN_OFFSET부터 TURN_COUNT개를 순회한다.

표기 주의 — strtoul로 읽어 011이 정수 11로 저장된다. 값 충돌은 없지만 규격 표기와 달라지므로 출력·로그는 항상 %03u로 찍을 것.

금지 유형은 BinaryMaker가 빌드 시점에 제외하므로 psf에 남지 않는다. 다만 전국 16,372건 중 실제로 제외되는 것은 2,273건뿐이다 — 나머지는 진출 링크가 진입 노드에서 약 12 m 떨어진 다른 노드에서 시작해(교차로가 방향별로 여러 노드로 분할됨) 애초에 회전 후보가 아니기 때문이다.

8. 구조체 정의

CreateData/src/DataFormat.h와 MapMatchSvr/src/DataFormat.h에 동일하게 반영해야 한다. 구조체명은 구·신 구분 없이 하나를 유지한다. 

#pragma pack(push, 1)

typedef struct sTurnInfoDisk        // 21 bytes
{
    uint64      qwInLinkID;         // 진입 링크 ID
    uint64      qwOutLinkID;        // 진출 링크 ID
    sint16      nTurnAng;           // 회전 각도 (Degree, -180~180)
    uint16      nTurnType;          // MOCT 회전제한유형 (011 은 11 로 저장)
    uint8       nTurnOper;          // MOCT 회전제한운영 0:전일제, 1:시간제
} TURN_INFO_DISK, *PTURN_INFO_DISK;

typedef struct sLinkInfoData        // 122 bytes
{
    uint64      qwLinkID;           // 링크 ID
    uint32      dwSgmtOffset;       // 세그먼트 시작 Offset
    uint16      wSgmtCount;         // 세그먼트 개수
    uint32      dwTurnOffset;       // 회전 정보 Offset
    uint8       nTurnCount;         // 진출 링크 개수
    uint8       nMaxSpeed;          // 제한 속도 (km/h)
    double      dfLen;              // 링크 길이 (m)
    uint8       nRoadRank;          // 도로 등급
    uint8       nConnect;           // 연결로 코드
    uint8       nRoadType;          // 도로 유형
    uint8       nLanes;             // 차선 수
    uint8       nRestVeh;           // 통행제한차량 (현재 매칭 판정 미사용)
    uint8       nRoadUse;           // 도로사용여부 (현재 매칭 판정 미사용)
    char        szRoadName[46];     // 도로명
    uint64      qwStNodeID;         // 시작 노드 ID
    uint32      dwStNodeX;          // 시작 노드 X (Degree * 360000)
    uint32      dwStNodeY;          // 시작 노드 Y
    uint8       nStNodeType;        // 시작 노드 유형
    uint64      qwEdNodeID;         // 종료 노드 ID
    uint32      dwEdNodeX;          // 종료 노드 X
    uint32      dwEdNodeY;          // 종료 노드 Y
    uint8       nEdNodeType;        // 종료 노드 유형
    uint64      qwOppositeLinkID;   // 반대방향 짝 링크 ID, 0=없음
} LINK_INFO_DATA, *PLINK_INFO_DATA;

#pragma pack(pop)

9. 크기 검증 — 버전 필드를 대신한다

헤더에 버전 필드가 없지만, 엔진이 로드 시점에 5개 영역 전부를 검사한다. 구조체 크기가 바뀌면 여기서 걸려 기동이 중단되므로 조용한 오파싱은 일어나지 않는다. 

// MapMatchSvr/src/DataLoader.cpp — 영역마다 동일한 형태로 5회
if ((dwTurnInfoCount * TURN_INFO_SIZE) != dwTurnInfoSize)
{
    LOGFMTE("turn info size is not same!");
    return m_bLoad;              // false
}

// Server.cpp — 로드 실패는 기동 실패로 이어진다
if (!m_pcDataLoader->SetDataUpdate())
{
    LOGFMTE("binary data load failed!file=[%s]", m_strDataFile.c_str());
    Uninitialize();
    return false;                // 서버 기동 중단
}
한계 — 크기가 바뀌지 않는 변경(같은 uint8 필드의 코드 의미만 바뀌는 등)은 이 검사로 잡히지 않는다. 그런 변경이 필요해지면 그때 버전 도입을 다시 검토할 것.

배포 제약 — CreateData와 MapMatchSvr는 반드시 함께 재빌드·배포해야 한다. make는 src/에 만들고 실행은 bin/에서 하므로 make install을 빠뜨리면 구버전이 돌아 구포맷 psf가 생성된다.
