구간단속 — 기존 2테이블 재사용 설계 신규 테이블·컬럼 0개

새 테이블이나 새 컬럼 없이, 개방형·폐쇄형에 이미 쓰고 있는 base_roadlink + base_tollgate 두 테이블만으로 구간단속을 구현하는 방안입니다.

0. 배경·해결 방식

기존 설계는 구간단속을 base_roadlink의 LINE 좌표를 버퍼링한 폴리곤 하나로만 판정합니다. 이 방식의 한계와, 구간단속을 "거리·평균속도를 계산하는 폐쇄형"으로 취급했을 때의 해결 방식을 함께 정리하면 다음과 같습니다.
문제원인해결 방식
인접 상/하행 도로와 간격이 좁으면(3~10m) 방향 구분 불가 point-in-polygon은 좌표 근접만 보는데, GPS 오차 감안한 zone_radius가 그 간격보다 큼 base_tollgate.link_id로 진입/진출을 정확히 매칭 — 반대 방향은 ID 자체가 달라 안 걸림
회랑이 링크 중간에서 시작·종료되면 거리 오차 base_roadlink.coords가 4~9점짜리 단순화된 좌표라 실제 도로 곡선보다 짧게 잡힘 base_tollgate.lon/lat는 링크 중간 아무 곳이나 찍을 수 있는 점 좌표 — 회랑 좌표 대신 진입~진출 사이 실시간 누적 이동거리로 계산 
진입점(I) 감지 → 세션 시작(진입시각, 누적거리=0)
    │  GPS 올 때마다: 누적거리 += 실제 이동거리   (중간 링크를 미리 알 필요 없음)
진출점(O) 감지 → 평균속도 = 누적거리 ÷ 경과시간 → speed_limit_kmh 비교 → 위반 판정
base_roadlink는 역할이 그대로입니다 — Layer 1 후보 필터(이 GPS가 구역 근처에 왔는지)만 담당하고, 정밀 판정·거리계산은 base_tollgate+세션 누적으로 넘어갑니다. 그래서 coords의 정밀도는 더 이상 중요하지 않습니다.

4. 판정 로직

C++ 의사코드는 문서에서 제거하고 별도로 기억해두었습니다 — 실제 소스 코딩 시 참조합니다. 골자는 base_tollgate의 gate_div='I' 진입을 link_id로 정확히 매칭해 세션을 시작하고, 세션 진행 중엔 매 GPS마다 base_roadlink 폴리곤으로 "아직 회랑 안인지"를 재확인(벗어나면 5절 방식대로 조용히 폐기)하면서 실제 이동거리를 누적하다가, gate_div='O' 진출을 만나면 누적거리÷경과시간으로 평균속도를 계산해 위반 여부를 확정하는 것입니다. 폐쇄형 판정 함수와 거의 동일한 코드 경로라 gate_div만 다르고 나머지는 재사용 가능합니다.

5. 예외 처리 — 중간 교차로 이탈

구간단속 구역은 폐쇄형(톨게이트)과 달리 물리적으로 막혀있지 않은 일반 공용도로입니다. 중간 교차로에서 다른 길로 빠지는 건 완전히 합법적인 정상 주행이라, 막을 수도 없고 막아서도 안 됩니다.
구분폐쇄형(톨게이트)구간단속
중간 이탈 가능 여부불가능(물리적으로 차단된 구조)가능(일반도로, 정상 주행)
이탈 시 의미요금 누락 위험 → 확인 필요측정 데이터 미완성 → 애초에 판정 불가
처리 방식미종결(AUDIT)로 기록 남김세션만 조용히 폐기, 기록 없음
진입~진출 구간 전체를 완주하지 않으면 평균속도 자체를 계산할 근거가 없으므로, 위반이든 통과든 판정할 수 없습니다. 그래서 폐쇄형의 "미종결 AUDIT" 패턴을 그대로 가져오지 않고, 그냥 정상적인 무관한 주행으로 취급해 세션만 초기화합니다.
감지 방법내용
1차 — Layer 1 재사용 base_roadlink 폴리곤 판정을 진입 시점뿐 아니라 세션이 열려있는 동안 매 GPS마다 계속 수행. 폴리곤을 벗어나면 즉시 세션 폐기 — 교차로 이탈을 지체 없이 감지
2차 — TTL 안전망 터널·GPS 음영구간 등으로 일시적으로 매칭이 끊겨 Layer 1이 오탐할 가능성에 대비한 백업. 정상 주행 시간보다 충분히 긴 TTL로 설정해, Layer 1이 놓친 경우만 뒤늦게 정리

6. 주의사항

  • 테이블 코멘트 갱신 권장 — base_tollgate 코멘트가 "영업소 마스터"로 돼 있는데, 구간단속 진입점은 영업소가 아닙니다. 기능엔 무관하지만 "폐쇄식·구간단속 공용 입출구"로 갱신 권장.
  • 세션 누적거리 로직 전제 — 폐쇄형 설계에 이미 언급된 누적거리 단계가 구현돼 있어야 그대로 재사용 가능합니다.
  • 게이트 link_id 공유 시 동시 트리거 가능성 — 세션의 inSpeedZone 플래그로 순서를 구분하므로 문제는 없지만, 등록 시 인지 필요.
  • 모든 구간에 필요한 건 아님 — 상/하행 혼동 우려가 없는 단순 도로는 기존 폴리곤 방식만으로도 충분할 수 있어, 필요한 구간에만 선택적으로 적용하면 됩니다.
